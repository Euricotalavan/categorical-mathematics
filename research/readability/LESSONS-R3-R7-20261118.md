## 2. 最重要的失敗原因

### 2.1 把可以測的指標，錯當真正的目標

頁數、每頁可擷取字元、段落數、ZIP CRC、PDF 文字比對和編譯成功都容易自動量測；**真正要解決的是讀者理解與持續閱讀時的摩擦**。前幾輪投入大量作業在技術驗證與微調，但使用者仍明確回報擁擠。因此工程「通過」只能證明工程層，不能宣稱內容與閱讀層也通過。

### 2.2 只縮短句子，不會自動讓版面舒適

LaTeX 會自動重新排頁：刪掉前面的字，後面的命題、例題與證明會向上填補。文字更少、頁數更少，仍可產生同樣飽滿的頁面。甚至為了「避免空白」而再塞下一個閱讀單位，會破壞概念的自然停頓。不能以頁數減少作優化 KPI。

### 2.3 只增加空行或分段，也可能更難讀

分段應對應真正的數學任務，例如：明確寫出測試資料、驗證存在、證明唯一、反方向、處理邊界、完成結論。隨機分段只讓文件膨脹，還可能造成孤立尾頁。**R7 的兩次撤回就是實際反例**：V0 Chapter 4 與 V2 Chapter 46 的習題解答因新分段只剩最後一兩行單獨佔頁。改動需要從 PDF 前後頁回查，不是只看 TeX diff。

### 2.4 忘記先用已達標的代表節校準

唯一得到正面回饋的 V0 Chapter 1 是另外對話的獨立稿。前幾輪沒有先固定其**數學版本、文字用途、閱讀單位與視覺效果**作嚴格對照，便把局部調整擴及幾百頁。這使修訂量大量累積，卻沒有確定任何新增代表節真正達標。

**應採取的策略：**先選一段尚未達標、包含長證明／題解的代表文字，明列每句話的功能，做原稿／修稿同內容比較；經實際閱讀核可後，才把適用原則推廣到下一類內容。代表節校準不代表整卷驗收，也不是將獨立校準稿未核數學差異直接覆寫整卷。

### 2.5 把排版官當成能自行裁決數學瘦身的人

論證中的條件、量詞、型別、良定性、首次操作、反方向與關鍵理由，看起來也可能像「冗字」。排版官只能刪確定**不改含義**且沒有教學功能的重述；若要改寫定義、命題、證明或依賴，必須交給內容精修官核實，必要時由打厚官補足。**公式片段完全相同不保證英文敘述的語義相同。**

### 2.6 重複的版本與工具障礙耗掉專業工作時間

- Chat 本身**可以**解壓 ZIP、修改 LaTeX 和編譯 PDF；某次 Library／GitHub 工具不能取到某份二進位檔，**不能**概括成 Chat 不具備 ZIP 能力。應區分「檔案存在」「本回合有無掛載實體 bytes」「解壓縮工具是否可用」，先實測再向使用者求助。
- 受保護數學來源曾被文字修補碰到，必須恢復原件並改由衍生編輯層載入；不能單靠「更動是導讀文字」忽略固定來源 hash。
- PDF 雖能編出，**來源 ZIP 必須能在可恢復環境對應到那份 PDF**。Library 二進位重新封裝可能改變 bytes，應記兩份不同的 hash，再比對頁面／文字／引用，不猜測它們必然相同。
- 重新編譯一度逾時，遺留不完整 \`.aux\`，後續編譯因此報錯。必須分清楚「建置行程逾時／中斷」「輔助索引損壞」「LaTeX 正文錯誤」；乾淨修復暫存索引，再做正確重建，不能把逾時冒稱編譯失敗。
- V1/V2 使用跨卷引用：應依 **V0 → V1 → V2** 順序更新對應 AUX／引用索引，檢查相容的 PDF 檔名與連結。
- 曾用局部擴頁指令把正文推近頁腳；「沒報 overfull」不足以放行，仍要實際看正文與頁腳距離。

## 3. 往後行文編輯的具體決策規則

以下是**建議的工作方法**，不是要求立刻展開新一輪書稿製作。

1. **先建立閱讀問題單，而不是先動 TeX。** 每項記卷／章／節／PDF 物理頁、原文、讀者阻力、該段數學或教學功能、L（純排版）／E（非語義行文）／N（敘事先備）／M（數學）分類與負責者。
2. **先確定不能刪的東西。** 型別、量詞、定義的可操作條件、必要存在與唯一性、推論關鍵、反例、首次操作與有效的 Why 不因擁擠刪掉；可以刪的是無功能重述、同義反覆提醒和不必要轉場。
3. **不修改使用者已明令固定的字級、行距、段距、頁面邊界。** 以正式 ReadFlow R1 為唯一模板；在這段迭代中使用者特別要求「縮減文字跟排版」，而不是靠增加距離解決。局部分頁保護可以使用，但須有理由與回歸證據。
4. **每個修改應具有可檢查的功能。** 例：原文一句反覆解釋已明確的公式 → 刪去；一段同時包含存在與唯一 → 在真實的推理轉折處分段；把整節無端推往新頁、卻沒改善閱讀 → 撤回。
5. **先讓一個代表節真正可讀，再擴及同類問題。** 不把單一 93/100 主觀回饋當跨章節的學習成效；必須保留反例：長證明、繁複交換圖、習題詳解並不自動適用短定義的分頁策略。
6. **修改後看「同一閱讀單位」的前後頁。** 頁數／字元量僅作異常定位；查標題孤立、短尾頁、Remark/Why 分離、圖和公式距離、正文頁腳重疊、解答起始與上一題結尾的關係。
7. **全卷樣式完全不動，仍要重新檢查重新流動的頁。** 即使只刪一小段，往後跨頁結果可能改變。比對 source diff、公式／標籤、乾淨 XeLaTeX build、讀印版、PDF 可見邊界；全卷人工連續順讀與讀者回饋仍獨立。
8. **每個「通過」只說明證據真正能支持的層級。** A 內容保留、B 工程完整、C 閱讀驗收、D 數學終審分列。ZIP CRC／SHA、公式一致、頁面可渲染、字數降低，不代替 C 或 D。
9. **不要為了看起來有進度而滾動累積輪次。** 若幾輪的使用者回饋仍然是不夠可讀，停止擴大 patch 數量，回到根本的寫作／教學設計；保留已核工程成果，但不再以其代替品質決策。
10. **使用者停止時立即停止。** 保存前一個已交付版與本地未交付候選的不同身分；不再自動編譯、封裝、提交新稿或等待完成後再交；若另要求總結，只寫原創經驗，不上傳數學稿。
